Build something · Build brief

Build your first useful little tool

Have a recurring annoyance? Turn it into a small experiment. Here is how to take an idea from a sentence to something you can actually try.

By Sarah Forrest · Updated November 22, 2026

Download the PDF ↓
What you’ll leave with

A clear specification for a research-session tracker, plus a practical build and review process.

01 / Name the problem

Example: I open lots of tabs while researching, then forget which ones mattered. The first version of a solution could simply let me save useful links during a named session. Write the problem in your own words before choosing a tool.

02 / Sketch the smallest version

Start with a normal webpage and manual link entry. A browser extension that observes tabs is a later version with additional permissions and privacy decisions. You can learn whether the idea is useful without collecting browsing history.

  • A session name and a Start button.
  • A manual Add link form for a title, URL and short note.
  • A list of saved links and a Stop button.
  • A way to delete a session and export its links.

03 / Build one interaction at a time

Help me build a local research-session tracker. First describe a simple screen with a session name, Start/Stop controls, a manual link form and a saved-links list. Use HTML, CSS and JavaScript with localStorage. No login, tracking, background browsing access or external API. After I review the layout, implement session creation, then adding links, then JSON export and deletion. Explain how I can test each step. Treat entered content as text, not HTML. Allow only http or https links.

04 / Use real content

Try the tool during one actual research session. Add a long page title and a link with query parameters. Stop the session, reload the page and export your notes. Ask yourself whether it helps you find something later. A polished screen is only part of a useful tool.

05 / Decide what belongs in version two

If manual saving is useful but slow, consider an extension with an explicit save-current-tab button. Define what it can read, when it runs, where data stays and how to remove it. Ask for the narrowest permissions required. Do not jump to passive tracking just because it is possible.

Your review checklist

  • Can I complete the main task without instructions?
  • Are empty states and errors understandable?
  • Can I undo mistakes or delete my data?
  • Does the export contain the right information?
  • Does the page work on a phone and with keyboard navigation?
  • Can I explain how the data is stored?
